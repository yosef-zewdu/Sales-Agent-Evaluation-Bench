# Tenacious-Bench v0.1 — Sales Agent Evaluation Bench

A domain-specific benchmark and preference-tuned judge for evaluating a Tenacious sales agent against honesty, ICP classification, tone, and constraint-compliance dimensions that τ²-Bench cannot measure.

**DPO/SimPO/ORPO preference-tuned judge/critic**

---

## Problem Statement

The closest existing benchmark for evaluating sales agents is τ²-Bench retail, which we attempted to run locally to assess the pass@1 score. However, τ²-Bench retail does not adequately represent our outbound lead sales agent. 

### Project Overview
This project addresses the gap in sales-domain evaluation by building **Tenacious-Bench v0.1**—a benchmark constructed from limited seed material using engineering creativity and synthetic data techniques. Our goal is to transform a small seed corpus (initial execution traces and probes) into a robust, machine-verifiable evaluation suite. Completing this project involves:
1.  **Auditing gaps** in existing benchmarks for B2B sales.
2.  **Synthesizing a 200-300 task dataset** using multi-LLM routing and judge filtering.
3.  **Training a preference-tuned judge** to detect specific business-critical failure modes.
4.  **Publishing open artifacts** (HuggingFace dataset, trained model, technical blog post) to contribute to the open evaluation community.

## Quickstart

**Validate a task against the schema and run the scorer:**

```bash
# Run scoring evaluator against the built-in example tasks
uv run python scoring_evaluator.py --task schema.json

# Or point at a specific task file
uv run python scoring_evaluator.py --task tenacious_bench_v0.1/dev/example.json
```

**Task Authoring Modes:**
We utilize four simultaneous authoring modes to ensure high-fidelity and diverse evaluation:
-   **Trace-derived (≈30%):** Real execution traces, redacted and restructured into (input, candidate output) pairs.
-   **Programmatic Sweeps (≈30%):** Parameterized templates populated via combinatorial expansion.
-   **Multi-LLM Synthesis (≈25%):** Hard cases generated by routing across model families and quality-filtered.
-   **Hand-authored Adversarial (≈15%):** Edge cases manually written to defeat the baseline system.

**Generation & Quality Control:**
```bash
# Run all generation modes
uv run python generation_scripts/trace_derived.py
uv run python generation_scripts/programmatic.py
uv run python generation_scripts/multi_llm_synthesis.py

# Quality gate: LLM-as-judge + Dedup + Contamination check
uv run python generation_scripts/judge_filter.py
uv run python generation_scripts/dedup.py
uv run python generation_scripts/contamination_check.py \
  --train tenacious_bench_v0.1/train/ \
  --dev tenacious_bench_v0.1/dev/ \
  --held_out tenacious_bench_v0.1/held_out/
```

**Quality Control & Contamination Prevention Details:**
-   **LLM-as-a-Judge:** Every task passes a pointwise judge (scoring coherence, verifiability, and clarity) and pairwise comparison. To prevent preference leakage, models that generate data never judge it.
-   **Contamination Checks:** Before entering the held-out partition, all tasks pass three gates:
    -   **N-gram overlap:** < 8-gram overlap with the training partition.
    -   **Embedding similarity:** Cosine similarity < 0.85 via a cheap embedding model.
    -   **Time-shift verification:** Ensuring signals are from a documented window, not generic placeholders.


**Build preference pairs and train the judge (Path B):**

```bash
# Build (chosen, rejected) pairs from execution traces + bench tasks
uv run python training_data/prepare_training_data.py \
  --train_partition tenacious_bench_v0.1/train/ \
  --traces artifacts/held_out_traces.jsonl \
  --probes artifacts/probe_library.py \
  --output training_data/preference_pairs.jsonl

# Train the LoRA judge (SimPO/ORPO via Unsloth + TRL)
uv run python training/train_judge.py --config training/hyperparams.yaml

# Run ablations with paired bootstrap significance test
uv run python ablations/bootstrap_test.py \
  --results ablations/ablation_results.json \
  --alpha 0.05
```

## Baseline Numbers 

| Metric | Value |
|---|---|
| Mechanism pass@1 (signal over-claiming probes) | 0.95 (95% CI: [0.90, 0.99]) |
| Baseline pass@1 (same probe set) | 0.80 (95% CI: [0.72, 0.87]) |
| Mechanism vs. Baseline Δ | +0.15, p=0.0335 |
| Signal over-claiming cost (P006–P009) | $34,260/year, trigger_rate=0.22 |
| Avg cost per task | $0.0199 |

**Delta A target for trained judge:** ≥ +0.05 over baseline (0.80 → ≥ 0.85) on Tenacious-Bench held-out, p < 0.05 paired bootstrap.
